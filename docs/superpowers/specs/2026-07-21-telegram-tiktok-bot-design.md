# Telegram TikTok Bot — Design Spec

**Date:** 2026-07-21

## Overview

A Telegram bot that accepts a TikTok URL, resolves it via the tikwm.com API, and sends back either a watermark-free video or a photo slideshow. An inline MP3 button lets users download the background audio. Because Telegram callback data is capped at 64 bytes, music URLs are stored in an in-memory TTL cache and referenced by a short ID.

---

## Architecture

Module-based Go project. Two modules under `src/modules/`:

- **tiktok** — HTTP client for tikwm.com + DTO + service interface
- **telegram** — bot setup, update loop, message/callback handlers, short-id cache

Dependency injection via `github.com/google/wire`. Config loaded from `.env` via `godotenv` in `main.go`.

```
telegram-bot/
├── .env
├── go.mod
├── main.go
├── wire.go           # wire injector declarations
├── wire_gen.go       # generated by wire
```

## tiktok module

### DTO (`tiktok.dto.go`)

`InfoResponse` carries all resolved data:

| Field         | Type       | Notes                                  |
|---------------|------------|----------------------------------------|
| `ID`          | `string`   | TikTok post ID                         |
| `Title`       | `string`   | Post caption                           |
| `Author`      | `string`   | Creator username                       |
| `Duration`    | `int`      | Seconds (0 for slideshows)             |
| `Cover`       | `string`   | Thumbnail URL                          |
| `NoWatermark` | `string`   | Watermark-free video URL               |
| `Watermark`   | `string`   | Original video URL with watermark      |
| `Music`       | `string`   | Background audio URL                   |
| `Images`      | `[]string` | Photo URLs; non-empty = slideshow post |

`IsImage() bool` — returns `len(Images) > 0`.

### Client (`tiktok.client.go`)

Calls `POST https://www.tikwm.com/api/` with `url=<tiktok_link>&hd=1`. Parses the JSON response and maps it to `InfoResponse`. Base URL is configurable via `TIKWM_BASE_URL` env var (defaults to `https://www.tikwm.com`).

### Service (`tiktok.service.go`)

```go
type Service interface {
    Info(ctx context.Context, url string) (*InfoResponse, error)
}
```

Thin wrapper over the client. Validates that the resolved URL is non-empty before returning.

## telegram module

### Cache (`telegram.cache.go`)

- `Put(musicURL, title string) string` — stores entry, returns 8-hex-char ID
- `Get(id string) (musicURL, title string, ok bool)` — returns entry if not expired
- TTL: 1 hour per entry
- Background janitor goroutine sweeps expired entries every 10 minutes
- Thread-safe via `sync.Mutex`

### Handler (`telegram.handler.go`)

**OnMessage:**
1. Ignore non-TikTok text; reply with a hint.
2. Handle `/start` command.
3. Send "Processing... ⏳" message.
4. Call `tiktok.Service.Info()`.
5. Store music URL in cache → build MP3 inline button (`mp3:<id>`).
6. If `IsImage()`: send images as media group (chunked to ≤10), then send caption + MP3 button as separate message.
7. Else: send video with caption + MP3 button.
8. Delete the "Processing..." message.

**OnCallback:**
1. Always answer the callback query (clears Telegram's loading spinner).
2. Parse `mp3:<id>` from callback data.
3. Look up URL in cache; if expired, reply with a re-send prompt.
4. Send audio file via `FileURL`.

### Bot (`telegram.bot.go`)

- Creates `tgbotapi.BotAPI` from `TELEGRAM_BOT_TOKEN`.
- Long-polling update loop (timeout = 60s).
- Dispatches `Message` updates to `OnMessage` and `CallbackQuery` updates to `OnCallback`, each in its own goroutine.
- Stops cleanly when `ctx` is cancelled.

## Error handling

| Scenario                        | Behaviour                                              |
|---------------------------------|--------------------------------------------------------|
| tikwm returns error / non-200   | Reply to user: "Couldn't fetch that video 😕 `<err>`" |
| Cache entry expired             | Reply: "That MP3 link expired ⌛ send the video again."|
| Music URL empty                 | MP3 button not shown                                   |
| Media group send failure        | Logged; bot continues                                  |

## Known limitations

- **FileURL delivery** — Telegram fetches the file from its servers. tikwm links can occasionally be blocked or time out. Mitigation: stream bytes via `client.Stream` and upload directly (left as a follow-up).
- **50 MB Bot API limit** — Long HD videos can exceed this. If `tgbotapi` returns an error on send, the error is logged; a user-facing fallback (reply with direct link) is a follow-up.
- **In-memory cache** — Lost on restart. Acceptable for a single-instance bot; replace with Redis if running multiple replicas.
